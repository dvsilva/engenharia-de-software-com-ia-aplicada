# Decision framework

## Concept

A decision framework replaces a judgment call with a fixed sequence of questions, so anyone who gives the same answers reaches the same recommendation. As a decision tree, each question either decides on its own or hands over to the next one, which keeps the result finite, auditable, and deterministic, with no model or network call involved. A task that looks like one thing is decomposed first, and the tree classifies each subtask separately. Since the answers are enumerable, the program can prove every branch with self-checks before it shows a result.

Questions can also be scored, each with a confidence between 0 and 1. A gate then fails the whole case when any single score falls below the threshold, so no average can make up for a weak answer, and a binary check placed before the questions, such as whether the data may legally be used, blocks the case before anything else runs. Which questions failed matters as much as the verdict, since a failure that time resolves calls for waiting rather than a no. A composite score weighs the questions with the Analytic Hierarchy Process (AHP): a pairwise comparison matrix on Saaty's scale of 1 to 9 says how much more each question matters than each other, the weights are the geometric means of its rows normalized to add up to 1, and the consistency ratio, the consistency index (λmax - n) / (n - 1) divided by the random index for n questions, must stay below 0.10 for the judgments to be trusted. A committee's matrices combine cell by cell by geometric mean (AIJ), which keeps the result a valid reciprocal matrix.

## How the course implements it

The AI-first foundations lesson of the AI systems architecture module turns its three-question checklist, which decides whether a component should be an AI agent or a deterministic rule, into a tool written twice with only the standard library: in **JavaScript**, the official version, and in **Python**, its mirror.

The three questions are booleans asked in order. A yes to the first, whether a finite rule covers more than 90% of the real cases, decides Regra determinística on its own. Otherwise a yes to the second, whether an error is costly and the action irreversible, decides Agente com Approval Gate obrigatório. Otherwise a yes to the third, whether the behavior changes with the input's context, decides Agente autônomo, com observabilidade completa, and three noes give Regra determinística (mesmo parecendo complexa, se é enumerável, é regra). A later answer never changes what an earlier yes decided. Decomposing a hybrid task classifies each subtask, a record with a name, a type, and the three answers, and returns new records with the classification added, leaving the input untouched.

The tool takes no arguments and reads nothing. It first runs its self-checks, covering all eight combinations of answers and the decomposition of the checklist's TrialForge protocol amendment, limited to the two of its four subtasks that map to a single set of answers. A failed check stops the program with exit code 1 before the demo. The demo prints the four branches of the tree with their answers and classification, then each of the two subtasks with its type, name, answers, and classification, and ends with a note on why the other two rows of the reference table are left out.

The versions report their self-checks differently: **JavaScript** prints an [OK] or [FALHOU] line per check and a total on standard output, while **Python** runs unittest, whose verbose report goes to standard error. Their demos differ only in layout. **JavaScript** labels the branches Caso 1 to Caso 4 and puts a subtask's type in brackets before its name, with the answers and classification on the next line. **Python** frames each block's title with rules of 72 equals signs and gives a subtask's name, type, answers, and classification a line each.

The single-agent lesson applies the second question at runtime. Its anatomy demo, also in **JavaScript** and in **Python**, passes every proposed action, a record with a type, whether it requires approval, and a function that executes it, through a gate. An action that requires approval never runs and answers the status aguardando_aprovacao with a message that names its type and the question behind the gate, and any other runs at once and answers the status executada with its result. Generating the ICF draft runs, while notifying ANVISA of an adverse event waits. Self-checks of the gate, the long-term memory ([conversation-memory](conversation-memory.md)), and the tool ([tool-calling](tool-calling.md)) print [OK] lines before the demo, and a failed one raises.

The gateway prototype of the specific AI patterns lesson ([ai-gateway](ai-gateway.md)) holds drafts at the same gate and adds a confidence threshold beside the second question. A CSR synthesis always goes to the gate, citing its costly and irreversible error, and any other draft does when its retrieval confidence is below 0.7 ([hybrid-search](hybrid-search.md)), citing the confidence with three decimals and the threshold. The gateway prints the reason, audits the pending request ([agent-observability](agent-observability.md)), shows the draft, and asks Aprovar? (s/n), and only s, trimmed and in any case, approves. A confident draft prints its confidence and skips the gate. **JavaScript** asks through readline only when standard input is a terminal, and otherwise reads all of it before the first question and takes one non-empty line per question, echoing it after the prompt, while **Python** calls input, which reads one line per question and echoes nothing.

The tiering prototype of the enterprise architecture lesson ([ai-gateway](ai-gateway.md)) narrows the gate back to the CSR synthesis alone, since an escalation by low confidence there only changes the model ([model-routing](model-routing.md)). It shows the draft and asks Aprovar? (s/n) the same way, with the same difference between the two versions' reading of standard input.

The decision framework lesson of the data processing and fine-tuning module asks four scored questions about fine-tuning, in a tool written in **JavaScript** and mirrored in **Python** with only the standard library: whether the task is narrow and repeated, whether prompt engineering, RAG, and routing are exhausted, whether there is enough good data, and whether the task is stable. Everything it decides on comes from the cases file beside it: the threshold, 0.6, the AHP matrix, and three Amplitude Seguros cases, each with a name, a task, the four scores, and its data governance. The governance gate runs first and blocks a case without a legal basis under LGPD, or with sensitive data and no DPA signed with the provider, before any weight or money is computed. A score at or above the threshold is green and any other red, any red fails the case, and the failed questions are listed by number. Failing only the data question makes the case eligible for the option to wait, which the tool prices with its financial analysis ([investment-analysis](investment-analysis.md)). The composite score, rounded to four decimals, is printed but never decides. Later lessons of the module import the tool's AHP and gate functions from the **JavaScript** file.

Twenty-five self-checks print an [OK] or [FALHOU] line each and a total, and when any fails the tool prints the total, raises, and exits with 1 before the demo. The demo prints the AHP weights with three decimals and λmax, the consistency index, and the consistency ratio with four, then each case with its governance, its four questions with their signal and score, and its composite score. Amplitude Auto passes and gets the financial analysis, Amplitude Saúde Empresarial fails only on data and gets the option to wait, and Amplitude Atendimento ao Cliente fails the first and fourth questions with plenty of data, so the answer is to keep prompt plus RAG. A committee of three hardcoded matrices follows, with each member's weights, the aggregate's weights and consistency ratio, and the three cases' composite scores under the file's matrix and the committee's, whose verdicts never change, since the gate ignores the weights. Four more self-checks and a grand total of 29 end the output. Both versions print the same report and demo, apart from the consistency labels, CI and CR in **JavaScript** and ci and cr in **Python**, and the Real Options block.

The dataset preparation lesson of the same module applies a strict gate of four booleans to sources of training data before any is collected ([dataset-preparation](dataset-preparation.md)): whether a source holds the task's ground truth, comes from real production, covers the real variation of formats, and passes compliance. Any false criterion rejects the source, and the failed criteria are listed. The tool, in **JavaScript** and in **Python**, runs eleven self-checks and then prints seven hardcoded Amplitude Seguros candidates as accepted or rejected, each criterion marked v or x, of which only the workshop estimate and the medical receipt pass.

The fine-tuning via API lesson reopens the four-question tool nine months later for Amplitude Saúde Empresarial, the case that failed only on data, importing the gate, the AHP weights, the questions, and the cases file from the decision framework lesson beside it instead of deciding anything new. Its reassessment tool, in **JavaScript** and in **Python**, raises the data score by the monthly growth the case's option to wait already projects, 0.03 times 9 months, rounded to two decimals, from 0.35 to 0.62, and the monthly volume by the mode of its monthly growth compounded over the same months, from 1,200 to 1,862, leaving the other scores untouched. Five self-checks run first, and a failed one raises before the demo. The demo prints the threshold, then the case before and after, each with its four questions, their signal, and their score with two decimals, its monthly volume, and its recommendation, which turns from keeping prompt plus RAG to fine-tuning, and a note closes the output.

## What usually goes wrong in other languages

- Assertions that can be switched off silently skip the self-checks: **Java**'s assert runs only with -ea, **C** and **C++**'s assert disappears under NDEBUG, which release builds define, **C#**'s Debug.Assert is removed from Release builds, and **Python**'s assert statement is removed under -O. The originals use the **Node.js** assert module and unittest, which always run, so a transcription to those languages compares values explicitly.
- Test frameworks that run only through their own command, such as **Go**'s testing package, **Rust**'s test attribute, and **JUnit**, never run when the program starts. The self-checks run every time, before the demo, so the entry point calls them.
- A **Rust** panic exits with 101, not 1, so a failed check prints its message and exits explicitly.
- Booleans print as true and false in **JavaScript**, **Java**, **Go**, and **Rust**, as True and False in **Python** and **C#**, and as 1 and 0 in **C++** unless std::boolalpha is set.
- Objects and dictionaries are references in **JavaScript**, **Python**, **Java**, and **C#**, so adding the classification to an input record changes the caller's list, which the **Python** self-check catches. A new record per subtask avoids it, and **Go** and **C++** structs are copied by value.
- The classifications are the checklist's exact text, accents included, which a **Windows** console only shows with UTF-8 output.
- A gated action's function must never run, so the gate returns before calling it, and its answer has no resultado field at all, which the **Python** self-check tests by the key's absence.
- A score exactly at the threshold is green, and only a failure of the third question alone counts as a lack of data, which the self-checks test.
- The committee's members and the cases are printed in a fixed order, which **Python**'s dicts keep, while **Go**'s maps and **Rust**'s HashMap iterate in random order, so those keep the members in a slice or a Vec.
- The anatomy demo prints its records the way each language shows them: **Node.js**'s util.inspect, over several lines when they are long, and **Python**'s repr on one line.
- The gateway's **JavaScript** version reads piped answers before any model call, so they never race the calls, and a missing answer counts as a rejection, while **Python**'s input raises at the end of input and the gateway ends with an unhandled error. Transcriptions read one line per question, flushing the prompt first, and the cases pipe one answer per gated draft.
- The gateway approves only s, so sim or y is a rejection, and a confidence of exactly 0.7 skips the gate.

## How close common targets get

Every target has conditionals, records, and standard output, so every target is a direct equivalent:

| Target                            | Fit               | Library                                                        |
| --------------------------------- | ----------------- | -------------------------------------------------------------- |
| **Python**                        | Direct equivalent | unittest from the standard library                             |
| **JavaScript** and **TypeScript** | Direct equivalent | The **Node.js** assert module                                  |
| **Go**                            | Direct equivalent | Explicit comparisons called from main and os.Exit              |
| **Rust**                          | Direct equivalent | Explicit comparisons and std::process::exit                    |
| **C#**                            | Direct equivalent | Explicit comparisons, because Release builds drop Debug.Assert |
| **Java**                          | Direct equivalent | Explicit comparisons, because assert needs -ea                 |
| **C++**                           | Direct equivalent | Explicit comparisons and std::boolalpha                        |

A tested **C++** transcription of the AI-first foundations tool exists, and the tested **Rust** transcription of the four-question tool sits with the investment-analysis examples.

## Tolerance

The tool is deterministic, so its demo is compared exactly, in either original's layout and with booleans in either case. The self-check report is free, since the originals write it in different formats to different streams, so the cases check only the exit code and that the demo's two blocks appear in order, with the note ending the output. The gate's answers in the single-agent demo are compared exactly too, as **Node.js**'s util.inspect, **Python**'s repr, or JSON, and so are its self-check lines, apart from the function names they quote. The four-question tool's gate, weights, consistency, and verdicts are compared exactly in either layout, with the self-check report free apart from its totals. Its cases also replace the cases file, once with another consistent matrix and other figures, so every number must come from the file, and once with an inconsistent matrix, whose failed consistency check must end the output with exit code 1. The gateway's cases pipe one approval and one rejection and accept the prompt with or without the echoed answer, since only **JavaScript** echoes it, and the tiering prototype's pipe one approval. The source gate's demo is compared exactly and its self-check report only by its total, and so is the reassessment's.

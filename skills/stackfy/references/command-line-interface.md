# Command-line interface

## Concept

A command-line program turns its arguments into one command, runs it, and reports through three channels: results on standard output, problems on standard error, and the outcome in the exit code, zero for success and anything else for failure. A grammar of subcommands and flags, parsed strictly and followed by a usage text whenever the input is wrong, is the common shape. An interactive program instead keeps a session open: it shows a prompt, reads one line from standard input, answers it, and asks again until a command such as exit ends the session.

## How the course implements it

The song highlights lesson of module 2 is an interactive chat on **Node.js**'s readline/promises. Its only flag, --user, takes the next word as the user when there is one and it is not empty, and other words are ignored. It prints a rule of 60 ═, the title 🎵 Recomendador de Músicas com Memória (LangGraph) indented by two spaces, the rule again, a blank line, Digite suas mensagens abaixo. Digite "exit" para sair., and a blank line. The template then prints 👤 Usuário: and the user when there is one, 📝 ID da Sessão: and the thread id ([conversation-memory](conversation-memory.md)), and a blank line, and when its memory store finds anything about the thread, which it never does, 📚 Informações do usuário carregadas: and what it found. The final version first prints ✅ Memória configurada: PostgreSQL once its checkpointer is ready, then always prints 👤 Usuário: with the user or anonymous, 💬 Thread da Conversa: and the thread id, and a blank line, and when the preferences store knows the user ([sql-database](sql-database.md)), 📚 Informações do usuário carregadas:, the stored information, and a blank line. It then asks the graph ([state-graph](state-graph.md)) for a greeting with Olá! Me apresente de forma amigável e pergunte sobre meu nome e preferências musicais., or, for a known user, with Inicie a conversa de forma casual mencionando o que você sabe sobre mim e recomende uma música!. Every answer prints as AI: and the content of the graph's last message followed by a blank line, and every answer after the greeting also starts with a blank line. The prompt is Você:, with a space after the colon and no line break. A line that is empty after trimming asks again, a line equal to exit in any letter case prints a blank line, 👋 Até mais!, and a blank line, and any other line, spaces kept, is the next turn. The template then ends with 0, while the final version never exits by itself, because the **knex** pool of its preferences store keeps a timer and nothing closes it. A failed greeting prints ❌ Erro ao iniciar conversa: and the message on standard error and goes on. A failed turn prints ❌ Erro ao gerar resposta: and the message on standard error, then AI: Desculpe, encontrei um erro. Pode tentar novamente? and a blank line, and goes on. Any other failure, such as the final version's database being down, prints ❌ Erro fatal: with the message and the stack trace on standard error and exits with 1. The template's graph never fails, and the final version's nodes answer a failed model call with an apology of their own instead of failing.

The safeguard lesson of module 2 answers one message per run ([prompt-injection-defense](prompt-injection-defense.md)). It finds each flag anywhere among the arguments and takes the next word as its value when there is one and it is not empty: --user names the user, --message the message, and --prompt-path a file, relative to the working directory, whose whole content, line breaks and final newline included, becomes the message when there is no --message, since a --message leaves the file unread. --unsafe takes no value and turns the guardrails off. Without a user, or without both a message and a prompt path, it prints ❌ Error: --user and (--message or --prompt-path) flags are required, a usage line for npm run chat, and Available users: erickwendel (admin), ananeri (member) on standard error and exits with 1, and a user that data/users.json does not hold prints ❌ Error: User "name" not found and the same list of users the same way. Otherwise it prints a rule of 70 ═, the title 🔒 Guardrails & Prompt Injection Demo indented by two spaces, the rule again, a blank line, 👤 User: with the display name and the role in parentheses, 🛡️ Guardrails: with ✅ ENABLED (Safe) or ❌ DISABLED (Unsafe - Vulnerable!), a blank line, a rule of 70 ─, a blank line, 📋 Your permissions: with the permissions joined by a comma or None, a blank line, You: and the message, and a blank line. It runs the graph ([state-graph](state-graph.md)), prints 🤖 Assistant: with the content of its last message and a blank line, and exits with 0. Any failure, such as a prompt file that cannot be read, which is read before the user is looked up, prints Fatal error: and the error on standard error and exits with 1.

The notas-api CLI parses its arguments by hand, without an argument library. An optional task word comes first, followed by create --title, list with an optional --status of all, open, or done, complete --id, or remove --id. A command with a required flag fails when the flag is missing, when its value is missing or starts with two dashes, or when anything follows the value, in that order. List takes nothing or exactly the status flag and its value.

Each line of a listing holds the id, the status, and the title separated by tabs, and an empty listing prints No tasks found. Creating, completing, and removing print Created task, Completed task, or Removed task followed by the task or its id. A usage mistake, a validation failure, or a missing task prints its message and then the usage text on standard error and exits with 1. A store that cannot be read or written prints only its message and exits with 1, as [layered-architecture](layered-architecture.md) describes, and so does a store that fails while loading, before any argument is parsed.

OpsPilot's arena and bench parse their arguments by hand as well, more loosely: every word that starts with two dashes takes the next word as its value, and the bench's --no-replanner is the only flag without one. The bench takes --scenario (C1, C2, or C3 in any case, all of them by default), --max-iterations, and --no-replanner, and ignores other words. From unit 3, it also takes --strategies, a comma-separated list of react and plan-and-execute whose empty names are dropped, and --max-llm-calls, a positive budget. Both check the **OpenRouter** key first, report a usage mistake as Error: and the message on standard error with exit code 1, and also exit with 1 when a strategy fails or a scenario misses, after printing the whole report on standard output.

A response with an error field or without a conversation id prints Turno, the number, FALHOU:, and the raw response on standard error and exits with 1. The run ends with a rule, the estimated total, and the conversation id. Unit 5's version describes the real promptTokens and the local estimate in the header's second line, and each turn's line adds the conversation id and the answer's promptTokens, n/a when missing, right after the turn number ([context-management](context-management.md)). Unit 6 keeps the arena, the bench, and unit 5's script unchanged.

The governance check of the project management module, danger-config-routewise.py, parses its flags with argparse ([pull-request-governance](pull-request-governance.md)): --local reads the pull request from a mock file instead of the **GitHub** API, and --mock names that file, pr-mock-routewise.json in the working directory by default. ## What usually goes wrong in other languages

- readline/promises' question takes only a line that arrives while it waits and drops the others, so the song highlights chat answers only the first of several lines piped at once. The cases type each line after the prompt appears, which a reader of every piped line passes too.
- The runner waits for the prompt before typing, so a transcription shows it before reading. **Python**'s input and **C++**'s std::cin flush it, and **Go**'s fmt.Print and **C#**'s Console.Write write at once, while **Rust**'s print! and **Java**'s System.out.print keep a text without a line break in their buffers until flushed.
- Only the song highlights chat's blank check trims: exit with spaces around it is a message, answered with its spaces, while EXIT ends the session.
- A transcription of the song highlights final version exits after 👋 Até mais!, and the cases stop the program 15 seconds after the last line and check no exit code.
- Argument libraries, such as argparse and **Click** in **Python**, the flag package and **Cobra** in **Go**, **clap** in **Rust**, **picocli** in **Java**, and System.CommandLine in **C#**, print their own usage and error texts and exit with 2. Matching the original means parsing by hand, as it does, which is shorter than bending a library to its texts. The governance check is the exception: it uses argparse, and its cases never pass a flag it does not know, so any library fits.
- Every mistake has its own exact message: Missing command, Unknown command with the name in quotes, Missing required flag, Missing value for flag, Unexpected extra arguments, and Invalid arguments for the list command.
- A value that starts with two dashes counts as missing, so is an empty value, and an empty first argument counts as no command at all.
- A title with spaces arrives as one argument. Words after the value are extra arguments, never part of the title.
- Errors leave standard output empty. The message and the usage text each end with a newline, and the usage text never goes to standard output. The governance check is the opposite: its problems go to standard output.
- Columns are separated by tabs, not spaces.
- The default store lives in the working directory, not beside the program, and TASK_CLI_STORE_PATH is used as given, relative paths included, also in error messages.
- OpsPilot's messages are exact too: Missing required flag: --strategies, No valid strategies. Use: followed by the four names, --max-iterations must be a positive integer, Invalid --scenario. Use: C1, C2, C3, Unknown strategy with the name in quotes followed by Use: react, plan-and-execute, and --max-llm-calls must be a positive integer. The message about a missing key ends with a hint about **Node.js** commands that a transcription adapts to its own, so the cases check only its first sentence.
- The iteration limit follows **JavaScript**'s number conversion: an empty value means the default, and zero, a fraction, or text fails. An empty --input also falls back to the default request.
- A strategy that fails in the arena prints its header on standard output and ERROR: with the message on standard error, and the arena goes on with the next one.
- The safeguard lesson's usage line names npm run chat, which a transcription adapts to its own command, so the cases check only the rest of that line. Its Fatal error: line ends with the runtime's own error, which the cases only require to name the file.
- The safeguard banner has two spaces after 🛡️, and the prompt file's text is printed and sent as read, never trimmed, so a final newline leaves an extra blank line after You: and after 🤖 Assistant:.
- The assistant's usage line names node amplitude-seguros-assistente.js, which a transcription adapts to its own command, so the cases check only the rest of that line. Its text arrives as several arguments or as one, and both give the same text.
- The cases accept either line ending, so **Windows**' newline translation in text mode does no harm.
- conversa-longa.sh estimates tokens from wc -c, which counts UTF-8 bytes, so every accented letter counts twice, and divides rounding up in unit 4 and down in unit 5. Command substitution also strips the answer's trailing newlines before counting. **Python**'s len and **Go**'s utf8.RuneCountInString count characters, so the tested lengths come from the encoded bytes.
- curl ignores the HTTP status, so a failed turn is found by the body's error field or a missing conversation id, never by the status code, and the raw body goes to standard error as received.
- The ≈ and → in its lines are UTF-8, which a **Windows** console only shows with UTF-8 output.
- The command center's banner holds backslashes that **Python** keeps as written inside a plain string literal, with a SyntaxWarning on standard error, while most languages need them escaped or a raw string. Clearing the screen writes whatever clear writes, or only an error when TERM is unset, so the cases accept anything before each menu.

## How close common targets get

Every target reads its arguments and standard input and writes to both streams, so every target is a direct equivalent:

| Target                            | Fit               | Library                                                |
| --------------------------------- | ----------------- | ------------------------------------------------------ |
| **Python**                        | Direct equivalent | sys.argv parsed by hand, sys.stdout, and sys.stderr    |
| **JavaScript** and **TypeScript** | Direct equivalent | process.argv parsed by hand and the process streams    |
| **Go**                            | Direct equivalent | os.Args parsed by hand, os.Stdout, and os.Stderr       |
| **Rust**                          | Direct equivalent | std::env::args parsed by hand, println!, and eprintln! |
| **C#**                            | Direct equivalent | The Main arguments parsed by hand and Console.Error    |
| **Java**                          | Direct equivalent | The main arguments parsed by hand and System.err       |
| **C++**                           | Direct equivalent | argv parsed by hand, std::cout, and std::cerr          |

The tested **Go** transcription of notas-api sits with the layered-architecture examples, the tested **Python** transcription of OpsPilot with the reasoning-strategies examples, and the tested **Rust** transcription of the song highlights chat, which flushes its prompt, with the conversation-memory examples.

# Reasoning strategies

## Concept

A reasoning strategy decides how an agent turns a request into tool calls and an answer. ReAct interleaves thought, action, and observation in a single loop until the model answers in text, and the program, never the model, owns the stop criterion: after a fixed number of turns without an answer, the loop stops and hands the request to a person instead of failing silently. Chain-of-thought asks for the reasoning inside the same call, while any check of the answer costs at least one more whole call. Plan-and-execute first writes a short plan, runs each step with its own tool loop, and lets a replanner continue, adjust the remaining steps, or finish with the answer. Reflection wraps any strategy with a critic that judges the answer against the observations and, when it rejects it, runs the strategy again with the critique in front of the request, up to a fixed number of rounds. When every strategy returns the same result (the answer, a typed trace of thoughts, actions, observations, plans, critiques, and answers, and metrics of LLM calls and latency), an arena can run them side by side and a bench can score them by the state they leave behind instead of by their wording.

## How the course implements it

Unit 2 starts OpsPilot, the on-call copilot of a fictional e-commerce, in **TypeScript** with **LangChain** and **LangGraph** over **OpenRouter** ([chat-model](chat-model.md)). Each run gets a fresh in-memory store seeded with five services and six alerts, three of them firing (payment-api critical, auth-service high, and order-service critical, in that order), and three tools that list alerts and open and resolve incidents ([tool-calling](tool-calling.md), [layered-architecture](layered-architecture.md)).

ReAct runs **LangGraph**'s prebuilt agent ([state-graph](state-graph.md)) and turns its messages into the trace: the text beside tool calls becomes a thought, each call an action, each tool result an observation, and the final text the answer. Its LLM calls are the model messages in the run. When the run outgrows its step limit, the answer becomes "[Iteration limit reached after N steps. Partial result unavailable.]" with zero LLM calls and that answer as the whole trace.

Plan-and-execute caps the plan at the smaller of 8 and the iteration limit. The planner asks for the steps as structured output and, when that fails, falls back to a single step that asks to execute the request with the available tools. Each step runs its own ReAct agent on a user message with the original request, a line of rules that maps sev1 to sev4 onto the severities, the progress so far, and the current step, and keeps the last text the model wrote as the step's result. The replanner then sees the request, the finished steps with their results, and the remaining plan. Continue records a critique event saying the plan still holds, adjust replaces the plan and records it as a critique event, and finish ends with its answer. A failed replanner or a continue with nothing left ends with the progress as the answer, and reaching the step limit ends with the progress under a line saying the limit was reached, without calling the model. Without the replanner, the steps run in order and the progress is the answer. Its LLM calls count the planner, every model message of every step, and every replanner call.

Reflection is a decorator named reflect: followed by the base name. Its critic, also structured output, receives the original request, the observations of the latest run (or "(nenhuma)"), and the answer, and returns whether it approves and what to fix. On rejection, the base runs again on "[Critique - Round N]:", the feedback, a blank line, "Original request:", and the original request, and an empty feedback becomes "(sem feedback adicional)". It allows two rounds by default, treats a failing critic as approval, keeps the traces of every run plus one critique event per round (the feedback, or "[Crítico aprovou sem feedback]" when empty), and adds the critic calls to the LLM calls.

The arena and the bench are command-line programs ([command-line-interface](command-line-interface.md)). The arena runs the strategies it is given in order on the same request and prints, for each one, a header, the trace, the metrics, and the answer, and a strategy that fails prints its header and moves on. The bench runs three scenarios against ReAct and plan-and-execute: counting the critical firing alerts without opening anything, opening three sev2 incidents in a given order and resolving the first, and opening one incident for the oldest firing alert and saying how many remain. A scenario passes on the store's state and on the count the answer mentions, a miss lists its reasons, a preview of the answer, and a snapshot of the store, and a table closes the run.

Unit 3 keeps the strategies and runs each one on a message and a history ([conversation-memory](conversation-memory.md)). Its seed names the firing services payments, auth, and checkout, gives every service a tier, and adds runbooks for checkout, payments, and auth, and the agents get six tools ([tool-calling](tool-calling.md)), while the planner's prompt names only the five store tools. A registry maps react and plan-and-execute to their instances for the chat API, which wraps the chosen one with reflection on request ([rest-api](rest-api.md)). The bench takes --strategies to compare only some of them and --max-llm-calls, a budget it checks before each cell: once spent, it prints Budget atingido with the total and the budget, records that cell and every later one as skipped misses, prints a Skipping line for each later one, and stops. It also prints the model in use under its header, OPENROUTER_MODEL or (default createModel), the LLM calls of each cell and the running total beside ok or miss, and the total under the table.

Unit 4 gives ReAct, and the agent of every plan step, a shared Portuguese system prompt as the first message, which fixes the answer's format: **Resumo**, then **Achados** as a dash list, then **Próximos passos** with at most three items or Nenhum, without decorative emojis or extra sections, using only what the tools observed, and reading a "Relevant memories:" block as the on-call engineer's preferences ([semantic-memory](semantic-memory.md)). The replanner's prompt gains a line asking for the same format in its finish answer, while the planner and the critic keep theirs. A learning reflector reuses the critic's shape, a structured call on the request, to decide after each chat answer what to remember instead of whether to retry.

Unit 5 adds promptTokens to every strategy's metrics, the prompt tokens the provider reported for the run's calls, which only the chat API returns ([context-management](context-management.md)).

Unit 6 picks the strategy of every chat turn in the production graph's router ([state-graph](state-graph.md)). Unless the request forces one, the router asks the model, as structured output on the bare message, for a route of react, planExecute, or reflect and a one-sentence reason, under a Portuguese system prompt with a decision table: one-off lookups and simple tool calls go to react, multi-step requests, explicit plans, or several services to planExecute, and requests that need verification, are highly critical, or ask for a review to reflect, which is ReAct wrapped with the critic. A failed call, or an answer outside the schema, falls back to react with the reason fallback: router failed; using react. The chat body's strategy becomes an override of react, planExecute, reflect, or plan-and-execute, an alias of planExecute, and without one, reflect true forces reflect, so a strategy wins over the flag and react with reflect true runs without the critic. An override skips the model and gives the reason override from request. The route and its reason open the trace as a route event, with override true or false, and reach the metrics as route and routeReason, and llmCalls adds one for the router whenever it asked the model, however many attempts the call took ([model-routing](model-routing.md)), and nothing for an override. The shared system prompt gains a line that orders the **Achados** by severity, critical, high, medium, low, when the memories or the request ask to organize the shift ([semantic-memory](semantic-memory.md)). The arena and the bench still run the strategies directly.

Unit 9 adds team, a supervisor that hands the request to an analyst, a planner, and an executor over a shared blackboard ([multi-agent-orchestration](multi-agent-orchestration.md)), as a fourth route. The decision table gains a row that sends coordinated investigation, planning, and execution, complex requests that benefit from distinct roles, to team, the route schema and the chat body's strategy accept it, and the router never falls back to it. The team's metrics carry no promptTokens, so its turns add nothing to the stats' tokens and cost.

Unit 2's project also declares **Express**, mysql2, and **Sequelize**, which its constitution plans as infrastructure, but imports none of them, so transcriptions leave them out.

The single-agent lesson of the AI systems architecture module writes ReAct by hand, without a framework, in **JavaScript**, the official version, and in **Python**, its mirror, over **Ollama**'s native chat endpoint with gemma4:e2b ([llm-http-api](llm-http-api.md)) and one typed tool ([tool-calling](tool-calling.md)). Its agent drafts the assent section of the TrialForge informed consent form (ICF). A run starts from a Portuguese system message, which tells the model to call the tool instead of asking the user or writing from memory, and a user message with the protocol, the ANVISA jurisdiction, and the request, and every turn sends the whole history with the tool. An answer without tool calls is the draft. Otherwise only the answer's first call runs, outside the model, and the model's message and a tool message with the observation join the history. The orchestrator, never the model, stops after four turns by default, returning no draft, a flag that escalates to human approval, and the reason não convergiu em N volta(s). Each turn adds an entry to a development trail with its number, what the model decided, the call's arguments and observation, and its duration in milliseconds. The program runs seven self-checks of the tool, then simulates three requests: a protocol for 12 to 17 year olds, an adult protocol, and an adult protocol forced to a single turn so the escalation shows. It prints the draft and the trail of the first, warns when the model answers the second without the clause instead of escalating, and sends an escalation, or any unhandled error, to the Approval Gate. The lesson's anatomy demo contrasts two plans for the same question: chain-of-thought, one call that asks the model to think step by step briefly, and reflection, an answer followed by a second call in which the model rereads it and replies sim or não and what is wrong, printing each one's calls and duration and how many times longer reflection took.

## What usually goes wrong in other languages

- **Python**'s prebuilt ReAct agent answers "Sorry, need more steps to process this request." when its steps run out, instead of failing, so the iteration limit never shows. The tested transcription builds the agent's graph itself, as [state-graph](state-graph.md) describes.
- **LangChain** for **Python** sends structured output in another format by default, and the recorded answers only parse in the original's format, as [chat-model](chat-model.md) explains.
- An action prints as the tool name followed by its arguments as compact JSON in parentheses, keys in the order the model sent them and non-ASCII characters kept. **Python**'s json module adds spaces and escapes accents unless told otherwise.
- When one answer calls several tools, every action comes before the observations, because the trace follows the messages: the model's message with all its calls, then one tool message per call.
- The critic always judges against the original request and only the latest run's observations, never the enriched request or earlier runs.
- The plan prints numbered from 1, one step per line, and each finished step prints its result on the next line after three spaces and an arrow, so multi-line results continue unindented.
- Each strategy in the arena, and each scenario and strategy in the bench, starts from a newly seeded store, so incidents never leak between them.
- The arena's header and section rules use box-drawing characters. **Python** writes them as UTF-8 by default only from 3.15, so older versions on **Windows** need UTF-8 mode.
- When src is on the import path, a **Python** package named trace hides the standard library's trace module, so the tested transcription calls it tracing.
- The router's reason is the model's text, replayed, while the override and fallback reasons are fixed texts. The router sees only the bare message, never the summary, the history, or the memories.
- An answer that writes the route as JSON text instead of calling the function parses to nothing in **LangChain** for **JavaScript**, which is not retried, so the router falls back to react after one call, while arguments outside the schema fail inside the model's runnable and are retried once. The stand-in model answers some routes as text, and the cases replay both.
- Only the route names react, planExecute, and reflect, team from unit 9, and the alias plan-and-execute, select a strategy in the chat body. The arena's reflect:react answers 422 there.
- The single-agent limit counts model calls: when the fourth answer is a call, the tool still runs and the loop ends without a fifth request, which the cases check. The scenario forced to one turn passes the limit as an option, while the calibrated default stays four.
- The single-agent trail prints arguments and observations as JSON. **JavaScript** writes it compact and **Python** with spaces after the separators, which the cases accept, but both keep the model's key order and non-ASCII characters.
- Reflection's duration covers both of its calls, so the printed ratio is about two when both calls take as long as chain-of-thought's. Replies faster than a millisecond make chain-of-thought's duration zero, which prints Infinity or NaN in **JavaScript** and raises ZeroDivisionError in **Python**.
- An unhandled error in the anatomy demo ends the **JavaScript** version with exit code 0 after printing it, and the **Python** version with a traceback and exit code 1.

## Tolerance

The replay serves recorded model answers, so everything the programs print is compared exactly, except latencies, which may be any number of milliseconds, and incident ids, which are random (inc-, the epoch in milliseconds, a dash, and four hex digits). Ids also return to the model inside tool results, so those results are checked by their call id only, and no case resolves an incident it has just opened, because the recorded call would carry an id the new run never generated. Requests are compared by structure: the model, the temperature, every message's role and text, the call ids, the tools offered with their names, descriptions, and arguments, and the forced function of structured output. A provider error is checked by its status code, because each client words it differently.

In the single-agent lesson, the draft, the trail, and the escalation are compared exactly, in either original's wording, while the durations are free. The replay delays each of the anatomy demo's three calls by 300 ms, so the printed ratio of reflection to chain-of-thought must fall between 1.5 and 2.4. Its requests carry no call ids, because **Ollama**'s tool messages name the tool instead.

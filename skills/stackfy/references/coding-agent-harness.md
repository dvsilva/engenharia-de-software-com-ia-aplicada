# Coding agent harness

## Concept

A coding agent edits and runs a project on the developer's behalf. The harness is what the repository gives it so the work stays predictable: project memory that every request loads, instructions scoped to some folders, prompt files that become chat commands, terminal permissions that allow safe commands and deny destructive ones, and deterministic guardrails, such as a pre-commit hook that runs the type checker and the tests, which hold no matter what the model does. Spec-driven development orders the work in phases with human review between them: a constitution of non-negotiable principles, then for each feature a spec (what and why), a plan (how), and a list of small, ordered, testable tasks implemented one at a time. The harness is text and configuration, so it moves to any language, and only its stack-specific lines change.

## How the course implements it

Unit 1 builds notas-api with **GitHub Copilot** in agent mode. The project memory lists the stack (**Node.js** 22, strict **TypeScript** ESM, **zod**, node:test through **tsx**, and node:http), the commands, the folder of each layer, the conventions (layers never skip, external input is validated with **zod**, domain errors are translated at the edge, new logic comes with a test, typecheck and tests stay green, and nobody reads the environment file), and the workflow. A scoped instruction applies only to the service folder: pure functions where possible, and no imports from the HTTP layer.

Four prompt files turn spec-driven development into the chat commands especificar, planejar, tarefas, and implementar. Each resolves a feature by its number or path and writes numbered spec, plan, and tasks files side by side. The spec has context, user stories, numbered functional requirements, acceptance criteria in EARS ("when an event happens, the system shall respond"), what is out of scope, and open questions. The plan covers layers, data model, contracts, decisions, and the testing strategy. Each task fits in one commit, states when it is done, and starts unchecked, and implementing marks a task only after typecheck and tests pass, stopping for review after each cohesive slice. The lesson's specs folder holds the constitution and two features: task management over HTTP and CLI, and JSON persistence for the CLI.

The **VS Code** settings allow the npm scripts, node, the type checker, and the safe **Git** commands, and deny rm -rf, sudo, every push, and reading the environment file with cat, less, more, head, tail, or grep. A versioned hooks folder holds a pre-commit hook that runs typecheck and tests, enabled for each clone by pointing **Git**'s hooks path to it. The settings file came from OpsPilot, so it also allows commands notas-api lacks, such as arena and bench, and recommends **Spec Kit** prompts.

OpsPilot, from unit 2 on, keeps the same **VS Code** settings and runs spec-driven development through **GitHub**'s **Spec Kit**. Its own project memory lists the stack (**Node.js** 22, strict **TypeScript** ESM, **LangChain** and **LangGraph** over **OpenRouter**, **zod** at every boundary including the model's output, **Express**, MySQL through **Sequelize**, and node:test through **tsx**), the commands, and the conventions, and ends with a block that **Spec Kit** points to the current feature's plan. The constitution's eight principles put the agent graph at the center, keep the layers in one direction, validate every boundary, turn predictable failures into domain errors, make tests part of every task, keep secrets out of the repository and load variables with **Node.js**'s env-file flag, require a reviewed spec before code, and keep each task to one commit. **Spec Kit**'s agents and prompt files add the commands to write the constitution, specify, clarify, plan, break into tasks, analyze, check, implement, converge, turn tasks into issues, and update the project memory, and its folder holds the templates, the workflow with review gates, and the bash and **PowerShell** scripts that create features and check prerequisites, which the settings let the agent run. Each feature folder holds a spec, a plan, research, a data model, contracts, a quickstart, a requirements checklist, and tasks, for the reasoning nucleus and the reflection layer in unit 2.

Unit 3 amends the constitution to version 2.0.0, replacing MySQL through **Sequelize** with SQLite through node:sqlite, configured by OPSPILOT_DB and in memory for tests, records the amendment in a sync impact report, and updates the project memory's stack, commands, and current feature to match. It adds features for the chat API, the SQLite store, the provider status tool, the MCP server, and the persistent conversation, and registers the MCP server for **VS Code** and **Cursor** in their mcp.json files, both running npm run mcp silently from the workspace folder ([model-context-protocol](model-context-protocol.md)).

## What usually goes wrong in other languages

- The project memory, the scoped instruction, the plan prompt, the implement prompt, the allow list, and the hook all name the stack, its commands, its validator, and its test runner. A transcription rewrites every one of them for the target, because an agent told to run npm test in a **Python** project runs commands that fail or do nothing.
- The hook guards types and tests together. A target without a type check step keeps only half of the guardrail, so **Python** adds **mypy** or **pyright** in strict mode, and compiled targets run their build.
- The allow list matches command prefixes, so allowing the interpreter allows any script it runs. The original allows node, and the tested transcription allows go knowingly, since go run runs any program.
- The deny list blocks reading the environment file only through the commands it names. Secrets stay safe because the constitution keeps them out of the repository, not because the list is complete.
- The scoped instruction's glob and text follow folder names. When a transcription renames a folder, as **Python** must for the HTTP layer, the glob and the text change with it.
- The specs describe behavior and stay valid in any language, while the constitution names a mandatory stack and the plans name files, libraries, and test runners. A transcription keeps the specs and rewrites the stack line and the plans.
- **Spec Kit**'s commands, templates, and scripts do not name the stack, so a transcription keeps them as they are.
- The prompt files and scoped instructions use **GitHub Copilot**'s frontmatter. Moving to another agent, such as **Cursor** rules, **Claude Code**'s CLAUDE.md and slash commands, or AGENTS.md, is a translation of its own, separate from the language change.
- The hook needs its executable bit, which copies on **Windows** and archives often lose, and each clone enables the hooks folder again.
- The UI prompts name **Angular** 21 constructs (standalone components, signals, input signals, @if and @for, routerLink, and .ts, .html, and .css outputs), so moving to another framework rewrites them in its terms, while the design tokens prompt, the briefing, the specs, the **Stitch** export, and the **Figma** image name no framework and stay as they are. The **Angular CLI**'s MCP server serves only **Angular**, so a transcription drops it or registers a documentation server for its own framework.
- **OpenSpec**'s skills and workflows name no stack, while cfp-platform's proposals, designs, tasks, and specs name **Angular** signals, **NestJS**, **class-validator**, **Jest**, and **Cypress**'s commands, so a transcription keeps the requirements and scenarios and rewrites those names in the target's terms.
- brag-bot's GEMINI.md names **Angular**'s constructs throughout, so moving to another framework rewrites it in that framework's terms, while its accessibility rules name no framework and stay. **Gemini CLI** reads GEMINI.md, so moving to another agent renames it too, such as AGENTS.md or **Claude Code**'s CLAUDE.md.
- The Context7 prompt names **Next.js**, npm, **Better Auth**, **better-sqlite3**, and **Tailwind CSS**, and the documentation topics it asks **Context7** for follow them, so a transcription rewrites the stack, the topics, and the commands for the target's libraries, while the sections, the stop rule, the **Playwright** check, and the output format stay. **Context7** also serves documentation for other languages' libraries, so the requirement holds.
- The Grafana MCP prompts name the endpoint, the service, and **Node.js** and **Fastify**, and ask for a file and line that a transcription moves, so a transcription keeps the queries and rewrites those names. The diagnosis report quotes pg-pool's own error, which another driver words differently, and the metric names of **Node.js**'s HTTP instrumentation, which change with the target's semantic conventions.

## How close common targets get

The harness is text, so every target is a direct equivalent. Transcriptions keep the guardrail consistent with these commands:

| Target                            | Fit               | Type check and tests in the hook                |
| --------------------------------- | ----------------- | ----------------------------------------------- |
| **Python**                        | Direct equivalent | **mypy** in strict mode and **unittest**        |
| **JavaScript** and **TypeScript** | Direct equivalent | **tsc** without emitting and node:test          |
| **Go**                            | Direct equivalent | go vet and go test                              |
| **Rust**                          | Direct equivalent | cargo clippy and cargo test                     |
| **C#**                            | Direct equivalent | dotnet build and dotnet test with **xUnit**     |
| **Java**                          | Direct equivalent | **Maven** or **Gradle** with **JUnit**          |
| **C++**                           | Direct equivalent | **CMake** with warnings as errors and **ctest** |

The tested **Go** transcription of notas-api, kept with the layered-architecture examples, carries the whole harness, while the **Python** one of OpsPilot, kept with the reasoning-strategies examples, leaves the **Spec Kit** harness out. The tested **React** transcription of pix-app, kept with the component-framework examples, rewrites the UI prompts for **React** and leaves the unchanged inputs and the MCP server out. The one of cfp-platform, kept beside it, rewrites the current **OpenSpec** specs for **React** and leaves **OpenSpec**'s skills, workflows, and archived changes out. The tested **Go** transcription of brag-bot, kept with the chat-model examples, restates GEMINI.md for **Go** and its templates and registers gopls's MCP server in place of the **Angular CLI**'s.

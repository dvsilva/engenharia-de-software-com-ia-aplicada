# Model fine-tuning

## Concept

Fine-tuning adapts a pretrained model to a task by training it further on examples. Supervised fine-tuning (SFT) trains on pairs of an input and the answer the model should give, and preference tuning, such as DPO (Rafailov et al., 2023), trains on pairs of a chosen and a rejected answer to the same input. Parameter-efficient methods such as LoRA (Hu et al., 2021) freeze the base weights and train small low-rank adapters, whose rank sets their size. The main hyperparameters are the number of epochs, each a full pass over the dataset, the learning rate, which managed providers expose as a multiplier of their own default, and the adapter's size.

A managed provider, such as **Vertex AI** for **Gemini** or **OpenAI**'s fine-tuning jobs, takes the dataset in its own format from storage, trains it as an asynchronous job, and publishes the tuned model behind an endpoint. The job goes through states, from pending and running to one of the terminal ones, succeeded, failed, or cancelled, so the client polls it: it waits between queries with exponential backoff up to a ceiling, so it never hammers the API, and retries a failed query a bounded number of times, so a transient network error does not end a follow-up that lasts an hour. Training is billed by the tokens of the dataset times the epochs.

Creating a job costs money, so the client validates every hyperparameter before any call, because a provider may accept an invalid value and silently replace it with its default, and requires an explicit confirmation before it creates anything. Validation fails fast and once, while retries apply only to reads after the call was authorized. Once the job exists, comparing the hyperparameters it applied with the requested ones catches a silent default. A tuned model is versioned by content: a SHA-256 of the dataset file identifies the data whatever its name or date, as **Git** and **Docker** identify content, and a model card (Mitchell et al., 2019) records the model's identity, lineage, hyperparameters, data statistics, timeline, and cost.

## How the course implements it

The fine-tuning via API lesson of the data processing and fine-tuning module tunes gemini-2.5-flash on **Vertex AI** with 200 Amplitude Seguros extraction examples, 120 workshop estimates and 80 medical receipts, prepared by the module's cleaning pipeline ([dataset-preparation](dataset-preparation.md)). Its tools are written in **JavaScript** and mirrored in **Python** with only the standard library. Each runs self-checks first, an [OK] or [FALHOU] line per check under == Testes: titles and a total, before its demo, as the module's other tools do ([decision-framework](decision-framework.md)), and those that reach **Vertex AI** call its REST API directly, with fetch and urllib, authenticated by the token gcloud auth print-access-token prints ([llm-http-api](llm-http-api.md)). The tools that read a job take its full name, projects/{project}/locations/us-central1/tuningJobs/{id}, from TUNING_JOB_NAME and GET it at /v1/ followed by that name on the regional endpoint, refusing to start without the variable.

The tracking tool converts an example of the canonical schema (instrucao, entrada, saida, and metadata) to **Vertex AI**'s supervised format: contents with a user turn whose text is the instruction, a blank line, and the input, and a model turn whose text is the output serialized as JSON. An example without an instruction, an input, or an output object is rejected. It also applies the dataset preparation lesson's promise about OCR: an example whose metadata.confiancaOcr is at least 0.85 is approved, one below is flagged for human review, and one without a confidence, never scanned, passes without the gate. Thirteen self-checks run first. The demo prints a workshop estimate and a medical receipt converted, as JSON indented by two spaces, the gate's counts for the four documents of the dataset preparation lesson, a hypothetical 62% scan, and a synthetic example, and then the job's state, base model, display name, start and end times, the duration between them in minutes and seconds with two decimals, as in 45min41.95s, the tuned model, and the endpoint. An error is printed after Não foi possível consultar o job agora, and the tool still exits normally.

The hyperparameter tool validates epochCount as an integer from 1 to 20 and learningRateMultiplier as a number from 0.1 to 10, listing every error in one message. Its demo blocks epochCount 0 before any call and recalls the real incident it prevents: **Vertex AI** accepted that job, which ran with its default epochs until it was cancelled by hand. It then reads the job and compares the requested 3 epochs and multiplier 5 with the applied ones: an applied value that is missing is reported as a provider's silent default, a different one as a divergence, and equal values match even when one is a string, compared as numbers. It ends with the training statistics: the number of examples, the billable tokens, and the mean, median, minimum, and maximum of the input and output tokens per example.

The automation tool requires GCP_PROJECT_ID as well and chains the whole process: convert, validate, upload with gsutil cp, only for a .jsonl file and a gs:// destination, create the job, and follow it, failing fast at any step. Creation posts baseModel, tunedModelDisplayName, and supervisedTuningSpec, with trainingDatasetUri and hyperParameters, to /v1/projects/{project}/locations/us-central1/tuningJobs, and refuses to call anything unless the options carry confirmar set to true. Following queries the job once, and while its state is not JOB_STATE_SUCCEEDED, JOB_STATE_FAILED, or JOB_STATE_CANCELLED, waits and queries again, starting at 5 seconds and multiplying the wait by 1.5, rounded, up to 60. Each query is tried up to three times, 3 seconds apart, before its error ends the follow-up. Its eighteen self-checks cover the upload command, the confirmation, the backoff, and the loop and the chain with injected functions, so no check touches the network or the clock. The demo shows creation blocked without the confirmation, then follows the job, printing each state it reads, the final state, and the endpoint, or the last error after Não foi possível acompanhar agora.

The versioning tool hashes dataset-treinado.jsonl, the 200 converted examples beside it, with SHA-256 over its bytes, reads the job, and builds a versioning record with the job, the base model, the display name, the dataset's URI and hash, the hyperparameters, the example and billable token counts, the tuned model, the endpoint, the creation and end times, and the state. The record adds an estimated cost, the duration from createTime to endTime priced at the module's reference rates for cloud GPUs (US$ 0.40 to 0.80 an hour for consumer GPUs and 2.50 to 4.00 for an H100), and the real cost, the billable tokens times the epochs times R$ 0.00002909, the rate the course's billing showed, each rounded to cents. It requires the job, the base model, the dataset's URI and hash, the tuned model, and the endpoint, and names whichever is missing. Fourteen self-checks run first. The demo prints the hash and the record as JSON indented by two spaces, then writes a Markdown model card beside the program, with sections for the identification, the lineage, the hyperparameters, the dataset statistics, the timeline, the cost, with the duration in whole minutes and rounded seconds, amounts with a decimal comma, and thousands separated by dots, a validity note, and a fixed section on the lesson's DPO job over 40 preference pairs, the ones in preference-dataset-amplitude.jsonl, each a user turn with a chosen completion scored 1.0 and a rejected one scored 0.0. The lesson ships the card both versions wrote for the production job.

The Dolly pipeline tool, an extra that tunes the same model on a public dataset, adapts the conversion to outputs that are plain text, which it never serializes as JSON, keeps the same confirmation and validation, caches gcloud's token for 55 minutes, retries a call once with a fresh token after a 401, polls from 15 seconds by a factor of 1.3 up to 60, and runs an inference on the tuned endpoint with generateContent at temperature 0. When started, it runs only its ten self-checks, with injected functions, and never calls the network. The lesson's other tools scale the dataset and prepare a public one ([dataset-preparation](dataset-preparation.md)) and reopen the decision to fine-tune with nine more months of data ([decision-framework](decision-framework.md)).

The LoRA and PEFT lesson shows the same job on a managed API that takes LoRA settings in its body ([parameter-efficient-fine-tuning](parameter-efficient-fine-tuning.md)). Its preview tool builds a POST to **Together AI**'s https://api.together.ai/v1/fine-tunes with a bearer token, the model meta-llama/Meta-Llama-3.1-8B-Instruct-Reference, a training file id, and a training_type of Lora with lora_r 8, lora_alpha 20, and lora_dropout 0 from the local adapter's configuration, on all linear modules. Without TOGETHER_API_KEY it prints that request as JSON indented by two spaces, with a placeholder key, and sends nothing, and with the key it sends it and prints the job, or stops with the status and body of a rejection. Six self-checks over the request run first.

## What usually goes wrong in other languages

- Three tools reuse earlier lessons of the module by a path relative to the program: the reassessment imports the decision framework tool, which reads its cases file beside itself ([decision-framework](decision-framework.md)), and the scaling tool and the Dolly starter import the cleaning tool ([dataset-preparation](dataset-preparation.md)). A transcription beside the lesson imports those lessons' transcriptions from the same relative paths, or carries the functions it needs and reads ../modulo-01-decision-framework/amplitude-seguros-casos.json, so it runs beside the originals of both lessons, as the cases do.
- **Vertex AI** serializes 64-bit integers as JSON strings, so epochCount, tuningDatasetExampleCount, and totalBillableTokenCount arrive as "3", "200", and "27353", while learningRateMultiplier is a number. Typed decoders accept them only when told: **Go**'s ,string tag, **serde**'s serde_with or a custom deserializer, **System.Text.Json**'s JsonNumberHandling.AllowReadingFromString, and **Jackson**'s coercion. **JavaScript** keeps the strings and multiplies them by coercion, and **Python** converts them with int() in the versioning record, so the cases accept either type in the record.
- A missing field is not a zero. The job created with epochCount 0 reads without epochCount, since proto3 leaves out a zero, and the comparison must report it as missing, so typed decoders keep the field optional, as a pointer in **Go**, an Option in **Rust**, or a nullable in **C#** and **Java**, and print undefined, None, or null for it.
- The two tools measure durations differently: the tracking tool from startTime with two decimals of seconds, 45min41.95s, and the versioning tool from createTime, rounded to whole seconds, 45min 42s, with the seconds of the record rounded to three decimals. The timestamps carry microseconds, which **JavaScript**'s Date truncates to milliseconds and **Python**'s datetime keeps, and both give 2742.003.
- An error status resolves fetch, so the **JavaScript** versions check it and report Falha ao consultar job: with the status and its reason, while **Python**'s urllib raises and reports HTTP Error with the same two. **Go**'s net/http, **reqwest**, and HttpClient never raise on a status, so a transcription checks it.
- Polling waits in real time, so the self-checks inject the wait and the query instead of sleeping, and a transcription keeps that seam. Only reads are retried, never creation, and the loop must also stop on a failed or cancelled job.
- The hash covers the file's bytes. Reading it as text and writing it back, or letting **Windows** convert line endings, changes it, so a transcription opens the file in binary mode.
- The model card goes beside the program, not in the working directory, without a final line break, named model-card-amplitude-auto-saude-m3-200.md in **JavaScript** and with -py before the extension in **Python**, and either name passes.
- **Together AI**'s address is hardcoded in both versions of the preview tool, so the cases point TOGETHER_BASE_URL, the variable its SDKs read, to the replay, and a transcription sends there when it is set while the request it builds and checks keeps the real address. An empty TOGETHER_API_KEY counts as missing.
- The **Vertex AI** address comes from GOOGLE_VERTEX_BASE_URL, falling back to the regional endpoint, as for content generation, and the token comes from running gcloud auth print-access-token, trimmed, which the cases answer with a stand-in.
- The **Python** versions name the hyperparameters in snake case in their messages and serialize the model turn's JSON with a space after each colon and comma, and the cases accept both.

## How close common targets get

Every target can run a process, make HTTPS requests, parse JSON, and compute SHA-256, so every target is a direct equivalent:

| Target                            | Fit               | Library                                                                     |
| --------------------------------- | ----------------- | --------------------------------------------------------------------------- |
| **Python**                        | Direct equivalent | urllib.request, subprocess, hashlib, json, and asyncio for the waits        |
| **JavaScript** and **TypeScript** | Direct equivalent | fetch, child_process.execSync for gcloud, and node:crypto                   |
| **Go**                            | Direct equivalent | net/http, os/exec, crypto/sha256, and encoding/json with the ,string tag    |
| **Rust**                          | Direct equivalent | **reqwest**, std::process::Command, **sha2**, and **serde_json**            |
| **C#**                            | Direct equivalent | HttpClient, System.Diagnostics.Process, SHA256, and System.Text.Json        |
| **Java**                          | Direct equivalent | java.net.http.HttpClient, ProcessBuilder, MessageDigest, and **Jackson**    |
| **C++**                           | Direct equivalent | **libcurl**, popen for gcloud, **OpenSSL**'s SHA-256, and **nlohmann/json** |

Google's SDKs, such as **google-genai**'s tunings and the **Vertex AI** SDK, read application default credentials instead of gcloud's token and shape the calls their own way, so transcriptions call the REST API, as the originals do. No tested transcription of the lesson exists yet.

## Tolerance

The jobs come from the cases, so states, times, durations, statistics, the versioning record, and the model card are compared exactly, and the requests by their method, path, and bearer token, in either original's types and names. The waits between queries are not measured, but the number of queries is, so a transcription must retry and poll as the original does. The self-check reports are compared only by their totals.

# Dataset preparation

## Concept

A fine-tuning dataset is a set of examples, each an instruction, the input the model will see, and the output it should give, usually stored as JSONL, one JSON object per line. Its quality decides more than its size: LIMA (Zhou et al., 2023) showed 1,000 curated examples beating 52,000 uncurated ones, the idea behind Andrew Ng's data-centric AI.

Preparation starts before collection, with a relevance gate that accepts a source only when it holds the task's ground truth, comes from real production, covers the real variation of formats, and may be used for training under compliance, so a single failed criterion rejects it. Extraction then turns each document into an example: an OCR engine reads the scanned image and a parser tolerant to each layout's labels finds the fields, or a multimodal LLM reads the image and answers the fields as JSON, and a schema check rejects an example with a missing field or an invalid amount before it reaches the file. Personal data is removed on the way ([pii-scrubbing](pii-scrubbing.md)).

Cleaning removes near-duplicates, such as a document sent twice or the same document read with OCR noise. MinHash (Broder, 1997) estimates the Jaccard similarity of two documents' sets of word shingles from a short signature, the minimum of each of k hash functions over the shingles, and LSH banding splits each signature into b bands of r values and pairs only the documents that collide in some band, which avoids comparing every pair. Each candidate pair is confirmed by its exact Jaccard similarity, and the later document of a confirmed pair is removed, as Lee et al. (2022) do for language model training data.

Balancing keeps one source from dominating. Temperature sampling, from T5 and mT5, weighs source i by its count to the power α, so α = 1 keeps the proportions and α near 0 tends to uniform, and mT5 uses α = 0.3. The largest remainder method (Hamilton) turns those weights into whole counts that add up to the target, and no source is given more examples than it has. Diversity is measured by the Shannon entropy H of the distribution over sources, in nats, and by the effective number of sources, the Hill number exp(H), the number of equally represented sources that would give the same entropy.

## How the course implements it

The dataset preparation lesson of the data processing and fine-tuning module prepares data for the Amplitude Seguros insurer's two extraction tasks: the insured person, the plate, and the amount from a workshop estimate (amplitude-auto), and the beneficiary, the procedure, and the amount from a medical receipt (amplitude-saude-empresarial). It has five tools, each written in **JavaScript** and mirrored in **Python** with only the standard library, and all but the multimodal one run self-checks first, printing an [OK] or [FALHOU] line for each, grouped under == Testes: titles, and a total, before a demo, as the decision framework tools of the module do ([decision-framework](decision-framework.md)). None takes arguments.

The relevance tool applies the four-criteria gate to seven hardcoded candidate sources, four for the workshop estimates and three for the medical receipts, each with four booleans and a justification. It prints each task's candidates as ACEITO or REJEITADO with a v or x before each criterion and the justification, and only the workshop estimate and the medical receipt pass.

The extraction tool reads four synthetic images beside it, in documentos-brutos, two workshop estimates and two medical receipts, each with different labels, by running the tesseract CLI in Portuguese twice per image: once for the text, which it trims, and once with the tsv configuration, averaging the confidence column of the rows whose confidence is not negative, divided by 100 and rounded to four decimals. A list of case-insensitive regular expressions per task takes the rest of the line after a label such as segurado, nome do segurado, beneficiario, or procedimento realizado, the plate as letters, digits, and hyphens, and the amount after valor total do reparo, total, valor, or valor cobrado, in Brazilian format, without dots and with the comma as the decimal point. The schema requires every field of the task and an amount above zero. Twenty-eight self-checks compare each document's fields with an answer key, ignoring accents and case for text. The demo prints each document's raw OCR text indented by two spaces, its confidence as a percentage with one decimal, the structured example as JSON, and the schema result, then writes dataset-amplitude-seguros.jsonl beside the program, one object per document with instrucao, entrada (the OCR text), saida, and metadata (caso, arquivoFonte, confiancaOcr, and valido), and closes with a note. An OCR failure is not caught, so the tool stops with an error before any document is tested.

The multimodal tool is the lesson's counterpoint: it sends each of the same four images to **Gemini** on **Vertex AI** with one generic prompt per task and no OCR or regular expressions ([llm-http-api](llm-http-api.md)). The prompt asks for JSON alone with exactly the task's keys and the amount as a number. It grades each answer against the same answer key, with text compared after removing accents, lowercasing, and trimming and the amount compared as a number, and prints each document's extracted JSON, its hits out of three fields, its latency, and its tokens. A document whose call fails prints [FALHOU] with the error and is left out, followed by how many failed and which. It then prints one [OK] or [FALHOU] line per graded field, with the extracted and expected values on a failure, the number that passed, and a summary with the total hits and their percentage, the mean latency, and the total tokens. With no document answered, it ends with an error and exit code 1.

The cleaning tool builds a simulated dataset of 47 examples from per-source templates, cycling through lists of names, plates, dates, amounts, and procedures by index: 28 workshop estimates from four sources (16, 5, 4, and 3) and 19 receipts from three (12, 4, and 3), with three planted near-duplicates, two exact resends and one copy whose label reads P1aca do veicu1o. Shingles are the sets of five consecutive words of the lowercased text with whitespace collapsed. The base hash of a shingle is djb2 (5381, then times 33 plus each character, in 32 bits), the 32 universal hash functions are (a × x + b) mod 2³¹ - 1 with their coefficients drawn from a linear congruential generator seeded with 42 (state × 1103515245 + 12345 in 32 bits, a = next mod 2,000,000,000 + 1 and b = next mod 2,000,000,000), and LSH uses 8 bands of 4 rows within each task. Pairs confirmed at an exact similarity of 0.55 or more lose their later example. Sixteen self-checks run first. The demo prints, for each task, the examples, the brute-force pairs, the LSH candidates with the reduction in percent, and the confirmed duplicates (28 examples, 378 pairs, 19 candidates, 95.0%, and 2 for the estimates, and 19, 171, 1, 99.4%, and 1 for the receipts), then the pipeline from 47 to 44 to 34 examples, balanced with α = 0.3 to targets of 20 and 14, keeping each source's first examples. Each task's counts per source, in the order sources first appear, with their shares, entropy, and effective number of sources follow, before and after balancing, and a note closes the output.

The fine-tuning via API lesson ([model-fine-tuning](model-fine-tuning.md)) imports the cleaning tool's functions from the dataset preparation lesson beside it, in both languages, instead of repeating them. Its scaling tool builds the 305 examples of the real tuning job with the same kind of templates, six workshops (60, 40, 30, 25, 15, and 10 examples) and five clinics (50, 30, 20, 12, and 8), indexing its lists by i × 7 + 3 for the surname and the date, i × 11 + 5 for the amount, i × 13 + 2 for the plate, and i × 5 + 1 for the procedure, with first names and surnames from pools of 41 and 37, plus five planted near-duplicates: three resends and two copies with OCR noise, P1aca do veicu1o and Va1or cobrad0. The same cleaning removes all five and balances to 120 estimates and 80 receipts, and the demo prints 305, 300, and 200, the 24,034 brute-force pairs and 454 LSH candidates, and each task's sources before and after with their entropy and effective number, after six self-checks. Its Dolly starter applies the same primitives to databricks-dolly-15k, 15,011 instructions written by people under CC-BY-SA-3.0, which the student downloads from **Hugging Face**. It keeps the 4,467 examples of the only three categories with a context (closed_qa, information_extraction, and summarization), maps instruction, context, response, and category to instrucao, entrada, saida, and the source, and deduplicates all of them together over the instruction and the input joined by a line break, since two questions about the same context are not duplicates. Of 778 LSH candidates among 9,974,811 pairs, 748 are confirmed, removing 396 examples, and the remaining 4,071 are balanced by temperature to 200, keeping each category's first examples (71, 66, and 63), which raises the entropy from 1.0877 to 1.0974 nats. Fourteen self-checks run first, and the summary prints the counts by category as JSON. The starter takes the file's path as its only argument, defaulting to the file beside it, and a missing file stops it with exit code 1 and the download command on standard error.

The final project lesson scales the same task to production with its own generator, again importing the cleaning tool, in both languages. Ten workshops (620, 470, 360, 280, 210, 160, 115, 80, 55, and 30 examples) and eight clinics (520, 380, 290, 200, 140, 95, 60, and 35) each write in one of three personas: a formal block in capitals, running text as in a letter, or an abbreviated export with fields between pipes. Every example draws from a global index i: a first name from 53 by i and a surname from 43 by i × 7 + 3, a plate from 31 letter triples by i with the digits 1000 + (i × 7 + 3) mod 9000, an amount of (i × 37 + 11) mod 700,000 + 39,000 cents with dots between thousands and a decimal comma, a date (i × 17 + 5) mod 220 days after January 5, 2026 as dd/mm/yyyy, a service from 24 by i × 5 + 2 or a procedure from 31 by i × 5 + 1, and one of three distractors by i mod 3, a policy and deductible, a claim number, or a broker for the workshops and the plan, a guide and CRM, or a corporate contract for the clinics, which the output never holds. An example whose index within its source is a multiple of 11 gets OCR noise: P1aca, ve1cu1o, Va1or, and cobrad0. Seven resends of each large source's first example bring the raw set to 4,107, and the cleaning finds 8 duplicates among 4,324,039 pairs and 9,325 LSH candidates, the seven planted ones and an organic pair of Instituto Saúde Plena at a similarity of 0.556, and balances the rest to 1,800 estimates and 1,200 receipts. After six self-checks, the demo prints 4,107, 4,099, and 3,000, each task's sources before and after with their entropy and effective number, and, in **JavaScript** only, the first balanced example of each task. The lesson ships the result as amplitude-seguros-dataset-producao-3000.jsonl, the final examples serialized by **JavaScript**'s JSON.stringify one per line in order, although the tool itself writes no file.

## What usually goes wrong in other languages

- The tools run the tesseract CLI, as both originals do, so the text and the confidences come from the same engine and model. Tesseract 5 with the fast Portuguese model, which **Homebrew**'s tesseract-lang and **Debian**'s and **Ubuntu**'s tesseract-ocr-por install, reads the first plate as QJk-4F82, while **tesseract.js** loads other models by default and may read the documents differently. Bindings to libtesseract, such as **gosseract**, read the same as the CLI.
- The text Tesseract prints ends with a line break, and both originals trim it before parsing and printing, so a transcription trims too.
- The regular expressions find the first match anywhere in the text, case-insensitively, and . stops at a line break, so (.+) takes the rest of the line in every engine. **Python** uses re.search, not re.match, and **Go**'s RE2 takes (?i) as a prefix.
- The OCR confidence is printed with one decimal and written with up to four, and **Python** writes whole amounts as 7940.0 where **JavaScript** writes 7940. JSON writers differ in spacing and in escaping accents, which **C#**'s System.Text.Json escapes unless given a relaxed encoder, and the cases accept all of these.
- The JSONL file goes beside the program, not in the working directory, with its keys in the original's order and a line break after each object.
- djb2 wraps in 32 bits: **JavaScript** masks with & 0xffffffff and reads it back unsigned with >>> 0, **Python** masks, **Go** uses uint32, **Rust** wrapping_mul and wrapping_add, **C#** uint in an unchecked context, and **Java** an int read with & 0xffffffffL. It hashes UTF-16 code units in **JavaScript** and code points in **Python**, which agree because the shingles are ASCII.
- The generator multiplies in 32 bits, which **JavaScript** does with Math.imul. The universal hash's product reaches about 2⁶³, so **JavaScript** computes it with BigInt, since a double loses its low bits, and **Go**, **Rust**, **C#**, and **Java** fit it in an unsigned 64-bit integer.
- The order of candidates never changes a result, so **Python**'s unordered sets and **Go**'s maps are fine for the buckets, but sources must keep the order they first appear in, which **JavaScript** objects and **Python** dicts do, while **Go** and **Rust** keep the keys in a slice or a Vec.
- Remainders are sorted in descending order with a stable sort, so a tie keeps the sources' order. **Go**'s sort.Slice and **C#**'s List.Sort are not stable, while sort.SliceStable, LINQ's OrderByDescending, **Rust**'s sort_by, and **Java**'s Collections.sort are.
- Assertions that can be switched off skip the self-checks, as the decision framework reference explains.
- Dolly's text is not ASCII. Whitespace is collapsed with a \s that matches Unicode spaces, such as the 2,322 non-breaking, thin, and hair spaces of the compatible examples, as **JavaScript**, **Python**, and **Rust**'s regex do, while **Go**'s RE2 matches only ASCII, so **Go** splits with strings.Fields. Seven characters lie beyond the BMP, which djb2 hashes as two UTF-16 code units in **JavaScript** and as one code point in **Python**, and the originals still confirm the same pairs.
- The production generator counts days from January 5, 2026 in UTC, with Date.UTC in **JavaScript** and date in **Python**, so local midnight never shifts a date, as it would with a local Date or **Go**'s time.Local.
- Amounts put dots between thousands with toLocaleString('pt-BR') in **JavaScript** and with a comma format swapped for dots in **Python**. **Go**, **Rust**, and **C++** have no locale formatting in their standard libraries, so they group the digits by hand, and **C#**'s and **Java**'s pt-BR cultures do it right.
- The Dolly file has no line break after its last record, so it holds 15,011 records in 15,010 lines, and the readers split on line breaks without dropping the last one.
- The **Python** versions print the counts by category as a dict, with single quotes and a space after each colon and comma, and drop the accents and the closing example from the Dolly starter's prose, and the cases accept both.

## How close common targets get

Every target can run a process, match regular expressions, and do 64-bit integer arithmetic, so every target is a direct equivalent:

| Target                            | Fit               | Library                                                                        |
| --------------------------------- | ----------------- | ------------------------------------------------------------------------------ |
| **Python**                        | Direct equivalent | subprocess for tesseract, re, json, and math                                   |
| **JavaScript** and **TypeScript** | Direct equivalent | child_process.execFileSync for tesseract, BigInt for the universal hash        |
| **Go**                            | Direct equivalent | os/exec for tesseract, regexp, encoding/json, and uint32 and uint64 arithmetic |
| **Rust**                          | Direct equivalent | std::process::Command for tesseract, **regex**, and **serde_json**             |
| **C#**                            | Direct equivalent | System.Diagnostics.Process for tesseract, Regex, and System.Text.Json          |
| **Java**                          | Direct equivalent | ProcessBuilder for tesseract, java.util.regex, and **Jackson**                 |
| **C++**                           | Direct equivalent | popen for tesseract, std::regex, **nlohmann/json**, and uint32_t and uint64_t  |

Tesseract itself must be installed with the Portuguese model, with brew install tesseract tesseract-lang on **macOS** or apt install tesseract-ocr tesseract-ocr-por on **Debian** and **Ubuntu**. No tested transcription of these lessons exists yet.

## Tolerance

The relevance and cleaning tools are deterministic, so their demos are compared exactly, with O(n²) or O(n^2) in the cleaning note, and their self-check reports only by their totals. The extraction tool's OCR text is compared exactly as Tesseract 5 with the fast Portuguese model reads it, apart from the case of the first plate's k, and each confidence must fall within 1.5 points of 94.1, 95.8, 95.7, and 95.9%, since the same engine gave 94.3 and 93.8 for the first document on **macOS** and on **Debian**. The JSONL file is compared line by line in either original's spacing, with a confidence between 0.9 and 1. The multimodal tool's answers are recorded, so its grades, hits, and token totals are compared exactly, while latencies are free. The scaling tool and the Dolly starter are deterministic too, so their summaries are compared exactly, over the Dolly file the cases download and check by its SHA-256, with either original's counts by category and the starter's prose with or without accents. The production generator is compared exactly as well, with or without the sample that only **JavaScript** prints.
